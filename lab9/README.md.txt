# Лабораторная работа №9. Таблицы

## Вариант 15
Ненулевые элементы заменить знаком: положительные → 1, отрицательные → −1, нули остаются 0.

## Файлы
- `table.py` — `row_sums`, `column_sums`, `diagonal_pattern`, `transform`
- `main.py` — ввод таблицы, вывод сумм, узора и результата `transform`
- `test_table.py` — проверки через `assert`

## Запуск
python main.py
python test_table.py

## Контрольные проверки
- `row_sums([[1,2,3],[4,5,6]]) == [6,15]`
- `column_sums([[1,2,3],[4,5,6]]) == [5,7,9]`
- `diagonal_pattern(3)` совпадает с образцом `0 1 1 / 2 0 1 / 2 2 0`
- `transform([[-2,0,3],[4,-5,6]]) == [[-1,0,1],[1,-1,1]]`
- `transform([]) == []`
- После `result[0][0] = 99` исходная матрица не меняется.

## Пояснения для защиты
1. **Почему `[[0] * columns] * rows` — ошибка?** Все строки ссылаются на один список: изменение одной ячейки затронет несколько строк.
2. **Чем `matrix.copy()` отличается от `[row.copy() for row in matrix]`?** Первое копирует только внешний список, строки остаются общими. Второе создаёт независимые строки.
3. **Почему `transform` не меняет исходную матрицу?** Она создаёт новый список `result` и новые строки `new_row`; исходные `row` только читаются.
4. **Почему `row_sums`/`column_sums` не используют `input()`/`print()`?** Это чистые функции: их можно проверить через `assert` без интерактивного ввода.
